## Что умеет приложение

- Лента постов, хранение в markdown, рендер в HTML на сервере (Markdig, «сырой» HTML
  запрещён — тело поста не может внедрить скрипт).
- Архив с поиском, тегами, сортировкой и пагинацией: `/posts?tag=csharp&q=async&sort=popular`.
- Время чтения и счётчик просмотров считает доменная модель, а не автор руками.
- Страницы и JSON API работают через одни и те же сценарии приложения.
- Защищённый записью API: создание, редактирование, публикация, архивация и удаление постов
  (заголовок `X-Api-Key`).
- OpenAPI-документ и интерактивная документация, health-check `/health`.
- При клоне репозитория сайт сразу наполнен демо-постами, а не пустой страницей.

## Архитектура

Четыре проекта и одно правило: **зависимости направлены только внутрь.**

| Проект | Ответственность | Зависит от |
|---|---|---|
| `DeomaBlog.Domain` | Сущности, value-объекты, инварианты | — |
| `DeomaBlog.Application` | Сценарии, DTO, порты (`IPostRepository`, `IClock`, …) | Domain |
| `DeomaBlog.Infrastructure` | EF Core + SQLite, репозитории, миграции, Markdig | Application, Domain |
| `DeomaBlog.Web` | HTTP-поверхность: страницы и API | все три |

**Проверка, которую я применяю на ревью:** если изменение схемы БД требует правки в
`Domain`, значит граница нарушена.

Подробности и компромиссы — в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Технологии

ASP.NET Core 10 (MVC + контроллеры) · C# 14 с nullable и warning-as-error · EF Core 10 и

собственный CSS и ~20 строк прогрессивного JavaScript · systemd, nginx, Let's Encrypt.

## API

| Метод | Маршрут | Доступ | Назначение |
|---|---|---|---|
| `GET` | `/api/posts?page&pageSize&tag&q&sort` | открыт | Архив с фильтрами и пагинацией |
| `GET` | `/api/posts/{slug}` | открыт | Пост с отрендеренным HTML |
| `GET` | `/api/posts/{slug}/related` | открыт | Похожие посты по тегам |
| `GET` | `/api/tags` | открыт | Теги с числом постов |
| `POST` `PUT` `DELETE` | `/api/posts…` | `X-Api-Key` | Создание, правка, публикация, архивация, удаление |
| `GET` | `/health` | открыт | Проверка живости и БД |

Ошибки отдаются в формате RFC 7807 (`application/problem+json`), ключ сравнивается за
постоянное время, а без настроенного ключа запись отвечает `503`, а не разрешает всё.

## Локальный запуск

```bash
git clone https://github.com/deomaaa/deomaItBlog.git
cd deomaItBlog

dotnet restore
dotnet run --project src/DeomaBlog.Web     # http://localhost:5080
dotnet test                                # юнит- и интеграционные тесты
```

Файл `blog.dev.db` и демо-посты создаются при первом запуске.

## Деплой

Продакшен — один VPS: Kestrel на `127.0.0.1`, nginx впереди для TLS, systemd для процесса.
Всё необходимое — в каталоге [`deploy/`](deploy), включая скрипт `deploy.sh`, который после
публикации дожидается успешного `/health`.

Есть и контейнерный вариант: `Dockerfile` и `docker-compose.yml`.

## Качество

- **62 теста** в CI на каждый push: 48 юнит-тестов домена и сценариев и 14 интеграционных,
  которые поднимают настоящий `Program.cs` на временной SQLite и проверяют HTTP-поведение,
  включая `401` на запись без ключа и `404` в формате problem+json.
- GitHub Actions собирает, тестирует с покрытием и публикует артефакт.
- Предупреждения компилятора считаются ошибками, nullable включён везде.
- Миграции применяются до старта Kestrel — деплой не может обогнать схему БД.
- Юнит systemd работает без root, с `ProtectSystem=strict` и доступом на запись только к
  каталогу базы.
